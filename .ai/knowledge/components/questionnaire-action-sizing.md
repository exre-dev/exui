# Questionnaire 操作按钮的响应式高度

Questionnaire 的 Previous、Skip、Next、Submit 复用共享 Button 配方，但原先还同时携带 `min-h-11` 与 `sm:min-h-0`。完整文档站样式中，应用层生成的基础 `min-h-11` 可以覆盖公开层的桌面重置，使默认按钮在桌面仍高达 44px，而共享 Button 默认高度为 36px。

导航按钮在桌面和移动端都直接使用 Button 的尺寸与密度，不再附加最小高度。即使把额外下限限定为 `max-sm:min-h-11`，也会让移动端的所有尺寸都变成 44px，与同尺寸的普通 Button 不一致。输入框与选项仍有独立的窄屏触控最小高度，不能将这条规则套到导航按钮上。

`QuestionnaireInput` 存在同一覆盖风险：Luma 的 `h-9` 不能抵消应用层的 `min-h-11`。它也必须仅在窄屏设置触控最小高度；否则即使桌面匹配 `sm:min-h-0`，实际高度仍是 44px。选项的高度则同时受最小高度和上下内边距影响，单独移除 44px 最小高度并不能收紧行高。保持最小高度而非固定高度，才能容纳说明和换行文字。

选项的桌面最小高度同样要限定为 `sm:min-h-9`，与 `max-sm:min-h-11` 互斥。基础 `min-h-9` 可能在应用层再次生成并覆盖公开层的窄屏触控最小高度；只检查桌面无法发现这个反向覆盖。

`Questionnaire.vrt.test.tsx` 在桌面和移动视口中，将四种尺寸、两档密度下的四种导航按钮与真实 Button 对比，通过跳过可选问题检查全部操作按钮。测试使用完整文档站样式；仅加载公开 CSS 无法覆盖跨样式层的优先级问题。

同一套件通过真实 `c-questionnaire-3` 检查写入式答案和单行选项的桌面高度、窄屏触控下限及输入取代单选的行为；用 `c-questionnaire-1` 的窄容器检查多行说明未被裁切。尺寸检查必须包含完整文档站样式，而不是只加载公开包样式。
