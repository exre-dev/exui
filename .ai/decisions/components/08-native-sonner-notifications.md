# 全局通知收敛到原生 Sonner 入口

最后更新：2026-10-19

状态：已接受\
模块：components\
日期：2026-10-19\
取代：[[components/06-single-ex-message-host]]

背景：ExUI 已同时公开原生 `Toaster/toast` 与建立在同一 Sonner 实例上的 ExMessage。加载、Promise 结果和按 ID 更新原生已支持；额外包装层主要维护容量、时序与任务失效规则，增加了消费者需要理解的入口和库内状态。

决策：删除 ExMessage 的运行时和类型公开面，不保留兼容壳，不把其控制器搬入另一个公开入口。保留 ExUI 对 Sonner 的呈现适配，业务生命周期归消费应用。结构见 [全局通知](../../architectures/components/notifications.md)，消费说明由 skill 和中英文升级指南维护。

考虑过先弃用一个版本，或删除名称但保留内部管理器。前者继续维持双入口；后者保留相同维护成本。用户批准直接删除并提供指南，因此选择以原生能力收敛，并明确接受旧容量与句柄语义不再由库保证。

代价：这是公开 API 的破坏性变更；下游要同步改导入、宿主和调用。需要取消、截止或卸载保护的应用须拥有自己的任务状态。旧文档家族及分享 ID 删除，升级指南放入入门目录。Changeset 明确记录破坏性差异；发布级别遵循维护者的发布决定，不用本地验证代替包发布或下游验收。

重新审视条件：多个消费应用出现一致且无法由原生通知 API 与应用任务状态清晰承担的跨应用契约，并有真实用例证明新增公共抽象的必要性。

依据：用户批准的 `.notes/archive/ex-message-removal/specs/2026-10-19-ex-message-removal-design.md`、同模块 RFC、根入口源码和独立打包消费契约。
