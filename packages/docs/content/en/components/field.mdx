Field: Composes a control, label, help text, and error state.

{/* exui-capabilities:begin:docs */}
## ExUI capabilities

**ExUI addition**

### Standalone Field composition

`Field`, `FieldContent`, `FieldLabel`, `FieldDescription` and `FieldError` compose settings rows and display values without form registration. Put a stable ID on the real focusable control; use it in `FieldLabel htmlFor`, and explicitly reference description and current error IDs in `aria-describedby`. Set `aria-invalid` when an error is present. These primitives do not infer IDs or inherit Form layout defaults. For noninteractive display values, render a text label with `asChild` and a `span`.

For the exact horizontal recipe, give each item its own inline-size container and query its child row. At 21.75rem (9rem heading + 12rem content + .75rem gap), use two columns and apply the content cap/alignment only to FieldContent. Below that threshold, stack and reset the content to full width. Use .25rem between label and description and .5rem between control and error. A wide page can still contain a narrow item.

```tsx verify
import { useId } from "react"
import { Field, FieldContent, FieldDescription, FieldError, FieldLabel, Input } from "@exre/exui"

export function SettingsField() {
  const id = useId()
  return <Field data-invalid>
    <FieldLabel htmlFor={id}>Email</FieldLabel>
    <FieldDescription id={`${id}-description`}>Used for project updates</FieldDescription>
    <FieldContent>
      <Input id={id} defaultValue="invalid" aria-invalid aria-describedby={`${id}-description ${id}-error`} />
      <FieldError id={`${id}-error`}>Enter a valid email.</FieldError>
    </FieldContent>
  </Field>
}
```

**ExUI adaptation**

### Checkbox inside FieldLabel

Selecting a `Checkbox` inside `FieldLabel` changes the checkbox fill and checkmark while keeping the label background unchanged. This applies to both checkbox cards and settings rows.

Read [Checkbox inside FieldLabel](./checkbox.mdx) for complete usage guidance.

**ExUI adaptation**

### Switch inside FieldLabel

When a `FieldLabel` contains a `Switch`, toggling the switch changes its track without filling the entire label background. This applies to card and settings-row labels. Use the label composition for a clickable switch row; avoid adding a selected fill solely to represent the switch state.

- [Live example](../../../../examples/c-field-1/)

**ExUI adaptation**

### Radio field selection

`FieldLabel` keeps its background unchanged when a nested `RadioGroupItem` is selected, including card and settings-row compositions. The radio circle and indicator show the selected state. Label clicks and arrow-key selection remain available; add an explicit background class if the composition needs a tinted row or card.

## Basic usage

Group the label, control, description, and error so validation stays associated with the field.

### Current example source excerpt

```tsx source="c-field-1"
import { Field, FieldDescription, FieldLabel, Input } from "@exre/exui"

<Field>
          <FieldLabel htmlFor={exampleId("profile-name")}>
            {<ExampleText>Full Name </ExampleText>}<span className="text-destructive">*</span>
          </FieldLabel>
          <Input
            id={exampleId("profile-name")}
            placeholder={copyExample("Enter your full name")}
            required
          />
          <FieldDescription>
            {<ExampleText>This name will be displayed on your public profile. </ExampleText>}</FieldDescription>
        </Field>
```

## Standalone fields

Compose `Field`, `FieldLabel`, `FieldContent`, `FieldDescription` and `FieldError` explicitly. Give each focusable control an ID and connect its label with `htmlFor`; include description and error IDs in `aria-describedby`. Set `aria-invalid` when an error is shown. Wrap `orientation="responsive"` fields in `FieldGroup` to provide their query container. Display-only content uses a span label with `FieldLabel asChild`.

The width and alignment example uses its own container at `21.75rem`: a `9rem` label, a `12rem` minimum control and a `.75rem` gap. Its control cap and alignment apply only above that threshold; narrow controls fill the row. Copy the complete source, including its scoped stylesheet, for that recipe.

Use [Form](../exui/form.mdx) and `FormField` when controls must bind to a validated draft.

```tsx verify
import { useId, useState } from "react"
import { Field, FieldContent, FieldDescription, FieldError, FieldGroup, FieldLabel, Input } from "@exre/exui"
export function StandaloneEmail() {
  const id = useId()
  const [email, setEmail] = useState("")
  const invalid = email.length > 0 && !email.includes("@")
  return <FieldGroup><Field orientation="responsive" data-invalid={invalid}>
    <FieldLabel htmlFor={id}>Email</FieldLabel>
    <FieldContent>
      <Input id={id} type="email" value={email} onChange={event => setEmail(event.target.value)} aria-invalid={invalid} aria-describedby={`${id}-description${invalid ? ` ${id}-error` : ""}`} />
      <FieldDescription id={`${id}-description`}>Account notifications.</FieldDescription>
      {invalid && <FieldError id={`${id}-error`}>Enter a valid email.</FieldError>}
    </FieldContent>
  </Field></FieldGroup>
}
```
